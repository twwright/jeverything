# Authenticated TypeSafe console review

Verified September 18, 2026 through the authenticated TypeSafe Playground UI. These are UI observations, not independent performance or calibration evidence. No credential was extracted. The console selected `jev-latest`; the raw resolved version and request IDs were not captured.

## Learn to TypeSafe

The Noul walkthrough changes a food-category judgment by adding explicit criteria and then structured state. Three tutorial requests were run. The displayed true probabilities were 60%, 77%, and 34%, respectively. The first two used the tutorial's initial context; the exact serialized empty/default state was not captured. The last used an ice cream sandwich description with the same sandwich criteria. These three values establish only what the UI displayed for those interactions. They do not establish accuracy, determinism, or Gateway behavior.

The Choice walkthrough compares bare color labels with descriptive color criteria and structured instructions. The Score walkthrough uses a fictionalized discussion of a macaque photograph to independently judge different contributors using ordered levels. Neither was run in this review. Independent scores do not form a conserved total, and a creative-contribution judgment does not establish legal ownership.

## Application examples

The resume example combines independent experience and technical-depth Scores, mentoring/LLM/open-source Nouls, career-progression Choice, and a ten-option talent-profile Choice. It was inspected, not run. Its date-based experience question is an opportunity to improve the example: compute elapsed time and employment overlap in code, then supply those facts. A demonstration does not establish validity for consequential employment screening.

The support-agent audit supplies a session event trace, tool calls and returned records. It asks independent questions about resolution, factual consistency, policy adherence, human follow-up, closing sentiment and predicted satisfaction. It was inspected, not run; the editor virtualizes long state, so not every event was captured. The architecture requires retrieved policy and actual tool results in state. A predicted future survey score remains a prediction, requiring later outcome validation.

The helpdesk example combines priority Choice, team Choice, deadline Noul and a 200-option tool Choice over a Wi-Fi follow-up request. It was inspected, not run. The preview confirms the option count; the virtualized editor did not expose every option at once. Large answer spaces remain relative choices: candidate retrieval, explicit rejection or review outcomes, deterministic argument validation and authorization are application responsibilities. A selected tool must never execute merely because it won a Choice.
